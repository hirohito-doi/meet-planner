# meet-planner 仕様

用語は [GLOSSARY.md](../GLOSSARY.md) に従う。設計判断の理由は [docs/adr/](adr/) を参照。

## 概要

- 複数人の都合を集めて、会議の日時を1つに決める Web アプリ(個人プロジェクト)。
- 流れ: 主催者が日程調整を作る → 回答者が回答する → 主催者が確定する。
- UI は日本語のみ。時刻は JST 固定。
- 通知(メール、Slack など)とカレンダー連携は持たない。リンクは主催者が手動で共有する。

## 技術構成

- TypeScript + Next.js。Node サーバーとして動かし、Vercel は使わない([ADR 0002](adr/0002-self-hosted-node-with-sqlite.md))。
- DB は SQLite で、Drizzle ORM を経由してアクセスする。
- Server Actions を入口にする。ロジックは Next.js に依存しない `server/` に置き、Action はそれを呼ぶだけにする。
- 各 Server Action では、入力値を検証(zod など)する。管理系の操作では、管理トークンを照合する。Server Actions は誰でも POST できる公開エンドポイントであるため。
- スタイリングは Tailwind CSS、パッケージマネージャーは pnpm。
- デプロイ先は未定。まずローカルで動かし、Docker で動く構成にしておく。

### モジュール構成

```
app/              画面と Server Actions。Server Action は FormData をオブジェクトに変換して server/poll を呼び、
                  PollError を画面のメッセージに変換するだけにする
server/poll/      日程調整のすべてのルールを持つモジュール。app/ は index.ts だけを import する
  index.ts        インターフェース
  ranking.ts      スコアと順位(純粋関数)
  store.ts        DB アクセス(外には見せない)
server/db/        Drizzle のスキーマと接続
lib/slot-grid/    候補を作る表のロジック(純粋関数、ブラウザ側で使う)
lib/jst.ts        JST の日時の計算と表示(サーバーとブラウザの両方で使う)
```

- `server/poll` のインターフェースは、日程調整の作成(`createPoll`)、回答画面用の読み取り(`readPoll`)、回答者としての登録(`join`)、回答者として開く(`openResponse`)、管理者として開く(`openAdmin`)の5つ。
- 回答者の操作(可否の保存、名前とコメントの保存)は、`openResponse` が返す照合済みのオブジェクトからだけ呼べる。編集用トークンの照合は `openResponse` の1か所で行い、使えないトークンなら null を返す。
- 管理系の操作(確定と取り消し、候補の追加と削除、回答の削除、タイトルと説明の編集、日程調整の削除)は、`openAdmin` が返す照合済みのオブジェクトからだけ呼べる。管理トークンの照合は `openAdmin` の1か所で行う。
- 入力値の検証(zod)、上限値、確定中の読み取り専用、重複判定、トークンの照合は、すべて `server/poll` の中で行う。
- 業務上のエラーは、種類付きの例外 `PollError` として投げる(見つからない、確定中なので変更できない、確定中の候補は削除できない、上限超過、入力が不正、など)。
- 候補の開始と終了は、DB には実際の時刻(UTC のミリ秒)で保存する。JST への変換と表示は `lib/jst.ts` にまとめる。
- DB を差し替えるためのリポジトリ層は作らない([ADR 0004](adr/0004-no-repository-layer.md))。
- トークンは DB にハッシュ値だけを保存する([ADR 0001](adr/0001-link-based-access-without-login.md))。

## アクセス

[ADR 0001](adr/0001-link-based-access-without-login.md) を参照。

- ログイン機能はない。日程調整の作成時に、回答用リンクと管理用リンクを発行する。
- 管理用リンクは推測できない長さのランダムトークンを含む。紛失すると復旧できない。作成直後の画面で、保存を強く促す。

## 入力値の制限

- 文字数は、前後の空白を取り除いてから数える。空白だけの入力は未入力として扱う。
  - タイトル: 1〜100文字(必須)
  - 説明: 0〜1,000文字
  - 回答者の名前: 1〜30文字(必須)
  - コメント: 0〜200文字
- 候補は、重複をまとめた後の件数で1〜25件。重複をまとめる前に送れる件数は100件まで(大量に送られたときに重い処理をしないため)。
- 候補の開始と終了は30分単位(JST で 0分か30分)。終了は開始より後で、長さは36時間以内。表では作れない値も Server Action に直接届きうるため、サーバー側で検証する。

## 日程調整

- 持つ情報は、タイトル(必須)、説明(任意)、候補(1〜25件)。
- 削除は管理画面から手動で行う。自動削除はしない。

## 候補の作成

[ADR 0003](adr/0003-one-drag-one-slot.md) を参照。

- 主催者はカレンダーで日付を選ぶ。選んだ日付が表の列になる。
- 表の1マスは30分。
- 各列では前日 18:00〜翌日 6:00 まで選べる。初期表示は日中付近で、上下にスクロールすると前日と翌日の時間帯が表示される。
- PC では、ドラッグ1回で候補が1件できる。1マスだけクリックすると30分の候補になる。既存の候補の上からドラッグを始めると、重なる新しい候補を作れる。
- スマホでは、開始マスと終了マスを順にタップして候補を作る。同じマスを2回タップすると30分の候補になる。開始を選んだあとに別の列をタップすると、開始を選び直す。
- 隣り合う候補や重なる候補は統合しない。重なった候補は横に並べて表示する。
- 作成中の候補(PC のドラッグ中のプレビュー、スマホで選んだ開始の印)は、作成後と同じ幅と位置で表示する。重なる場合は、既存の候補もそれに合わせて並び直す。
- 候補をクリック/タップすると選択され、画面下に「この候補を削除」ボタンが出る。長さの変更と移動はできない。
- 選択は、同じ候補、空いたマス、表の外のクリック/タップ、または Esc キーで解除する。空いたマスのクリック/タップは選択の解除だけを行い、候補の作成や開始の選択はしない。PC で空いたマスからドラッグした場合は、新しい候補を作る。
- 表の上で日付を外すと、その列の候補も消える。

### 表のレイアウト

- 列の幅は、表の幅を選んだ日付の数で均等に分ける。最大は表の幅の半分。最小は PC で 96px、スマホで 80px で、これを下回る場合は横スクロールにする。
- 候補ブロック1つの幅は最大 160px。
- 各列の右端には、候補ブロックを置かない余白(24px)を常に残す。スマホでは、ここをタップして既存の候補と重なる候補の開始を選ぶ。
- 候補の保存時に、開始日時と終了日時が完全に一致する候補を1件にまとめる。既存の候補と重複した追加分は捨て、既存の候補とその回答を残す。
- 候補を作ったときの列(日付)は保存しない。候補は実際の日時で表示する(例: 「12/4(水) 2:00-3:00」)。日付をまたぐ候補は「11/20(金) 23:00 - 11/21(土) 1:00」、0:00 ちょうどに終わる候補は「11/20(金) 23:00-24:00」と表示する。

プロトタイプはブランチ `prototype/slot-grid` の `prototypes/slot-grid.prototype.html` にある。

## 回答

- 回答は、名前(必須)、各候補への可否(○ / △ / ×)、コメント(任意、短い文字数制限)からなる。
- 名前の重複は許可する。
- 回答はまとめて送信しない。操作するたびに自動で保存する。
  - 回答画面を開くと、まず名前を入力するモーダルを出す。名前を入れて「回答を始める」を押すまで、表のセルとコメント欄は操作できない。
  - 「回答を始める」で回答者として登録する。この時点ではすべての候補が未回答。編集用トークンを発行してブラウザに保存する。
  - 編集用トークンを保存したブラウザで開き直したときは、モーダルを出さずに操作できる状態で表示する。トークンが使えない場合(主催者が回答を削除した後など)は、保存したトークンを消し、名前の入力からやり直してもらう。
  - 自分の列のセルをタップするたびに、空欄 → ○ → △ → × → 空欄 と切り替わり、すぐに保存する。空欄に戻すと未回答になる。
  - 画面の表示はタップした時点で変える。保存に失敗したときだけ元に戻し、「保存できませんでした」と表示する。同じセルを素早く何度もタップしたときは、最後の値だけを保存する。
  - 名前を変えるときは、自分の列の見出し(名前)をタップして同じモーダルを開き、「保存」で保存する。
  - コメントは表の下の入力欄に書き、入力欄から離れたときに保存する。保存できたことのメッセージは出さない。
- 同じブラウザからのみ、自分の回答を変更できる。他人の回答は上書きできない。
- 回答者は1つの日程調整につき最大50人。名前だけ登録して可否を1つも付けていない人も1人と数える。51人目は登録の時点で受け付けない。登録済みの回答者は、50人に達した後も自分の回答を変更できる。
- 回答者の列は、登録した順に並べる。名前や可否を変えても並び順は変わらない。
- 回答画面は表形式にする。行は候補(時刻順)、列は回答者で、右端にスコアを表示する。スコアが最も高い候補は強調表示する。スマホでは表を横にスクロールする。
- スマホで快適に回答できることを優先する。

## 集計

- スコアは、○=2、△=1、×=0、未回答=0 として合計する。
- 順位はスコアの高い順に決める。同点のときは × の少ない方を上位にし、それも同じなら開始日時の早い方を上位にする。
- 同点時に比べる「× の数」には、未回答を含めない。× は「参加できない」とはっきり回答したものだけを数える。
- 管理画面では、候補をこの順位で表示する。

## 確定

- 主催者は、候補を1件選んで確定する。自動では確定しない。
- 確定中は、回答画面に確定した日時を表示する。
- 確定中は日程調整全体が読み取り専用になり、回答、候補、タイトルと説明のいずれも変更できない。回答者としての登録もできない。
  - 例外として、主催者は確定中でも回答の削除と日程調整の削除ができる。
  - 確定中の候補も、ほかの候補も削除できない。候補を削除するには、先に確定を取り消す。
- 確定中に別の候補を選ぶと、取り消しを挟まずに確定し直せる。
- 確定は取り消せる。取り消すと、変更できる状態に戻る。

## 管理画面

管理用リンクからのみアクセスできる。

- 確定と確定の取り消し
- 候補の追加と削除(回答後も可能。後から追加した候補は、既存の回答者には未回答と表示される。削除した候補への可否は消える)
  - 追加の上限は作成時と同じ。既存の候補と重複をまとめた後に25件まで、1回に送れるのは100件まで。
  - 最後の1件の候補も削除できる。候補が0件の日程調整には、主催者が候補を追加するまで誰も可否を付けられない。
- 回答の削除(1人分をまとめて削除する)
- タイトルと説明の編集
- 日程調整の削除

## テスト

- Vitest: `server/poll` のテストは、インターフェースを通して外から見える振る舞いだけを確かめる(例: 確定中は回答できない)。DB はメモリ上の libsql に本番と同じマイグレーションを当てて使う。スコアと順位(`ranking.ts`)は場合分けが多いため、単独でもテストする。
- 候補を作る表の操作(マスの範囲から候補を作る処理)は純粋関数として切り出し、Vitest でテストする。
- Playwright: 日程調整の作成 → 回答 → 確定の主要な流れを E2E テストする。

## 対象外(最初の版)

- ログイン、アカウント
- 通知、カレンダー連携
- 多言語対応、JST 以外のタイムゾーン
- 自動削除
- 候補の長さ変更と移動
- 回答者側のドラッグ操作
- 場所、回答期限、主催者名などの項目
