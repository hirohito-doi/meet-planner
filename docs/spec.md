# meet-planner(○△× 日程調整)仕様

用語は [GLOSSARY.md](../GLOSSARY.md) に従う。設計判断の理由は [docs/adr/](adr/) を参照。

## 概要

- 複数人の都合を集めて、会議や集まりの日時を1つに決める Web アプリ(個人プロジェクト)。サービス名は「○△× 日程調整」。
- 流れ: 主催者が日程調整を作る → 回答者が回答する → 主催者が確定する。
- UI は日本語のみ。時刻は JST 固定。
- 通知(メール、Slack など)とカレンダー連携は持たない。リンクは主催者が手動で共有する。

## 技術構成

- TypeScript + Next.js。Node サーバーとして動かし、Vercel は使わない([ADR 0002](adr/0002-self-hosted-node-with-sqlite.md))。
- DB は SQLite で、Drizzle ORM を経由してアクセスする。
- Server Actions を入口にする。ロジックは Next.js に依存しない `server/` に置き、Action はそれを呼ぶだけにする。
- 各 Server Action では、入力値を検証(zod など)する。管理系の操作では、管理トークンを照合する。Server Actions は誰でも POST できる公開エンドポイントであるため。
- スタイリングは Tailwind CSS、パッケージマネージャーは pnpm。
- デプロイ先は未定。まずローカルで動かし、Docker で動く構成にしておく。

### モジュール構成

```
app/              画面と Server Actions。Server Action は型付きの引数を受け取って server/poll を呼び、
                  PollError を画面のメッセージに変換するだけにする。入力の検証は server/poll が行う。
                  照合に失敗して null が返ったとき(トークンが使えない)は、app で NOT_FOUND として扱う
server/poll/      日程調整のすべてのルールを持つモジュール。app/ は index.ts だけを import する
  index.ts        インターフェース
  ranking.ts      スコアと順位(純粋関数)
  store.ts        DB アクセス(外には見せない)
server/db/        Drizzle のスキーマと接続
lib/slot-grid/    候補を作る表のロジック(純粋関数、ブラウザ側で使う)
lib/jst.ts        JST の日時の計算と表示(サーバーとブラウザの両方で使う)
```

- `server/poll` のインターフェースは、日程調整の作成(`createPoll`)、回答画面用の読み取り(`readPoll`)、回答者としての登録(`join`)、回答者として開く(`openResponse`)、主催者として開く(`openAdmin`)の5つ。
- 回答者の操作(可否の保存、名前の変更)は、`openResponse` が返す照合済みのオブジェクトからだけ呼べる。編集用トークンの照合は `openResponse` の1か所で行い、使えないトークンなら null を返す。
- 管理系の操作(確定と取り消し、候補の追加と削除、回答の削除、タイトルと説明の編集、日程調整の削除)は、`openAdmin` が返す照合済みのオブジェクトからだけ呼べる。管理トークンの照合は `openAdmin` の1か所で行う。
- 入力値の検証(zod)、上限値、確定中の読み取り専用、重複判定、トークンの照合は、すべて `server/poll` の中で行う。
- 業務上のエラーは、種類付きの例外 `PollError` として投げる。種類は、見つからない(`NOT_FOUND`)、入力が不正(`INVALID_INPUT`)、上限超過(`LIMIT_EXCEEDED`)、確定中なので変更できない(`FINALIZED`)の4つ。確定中でも候補は削除できる。
- 回答画面用の読み取り(`readPoll`)は、候補ごとのスコアを順位順に並べた `ranking` も返す。管理画面の順位順の表示で使う。
- 候補の開始と終了は、DB には実際の時刻(UTC のミリ秒)で保存する。JST への変換と表示は `lib/jst.ts` にまとめる。
- DB を差し替えるためのリポジトリ層は作らない([ADR 0004](adr/0004-no-repository-layer.md))。
- トークンは DB にハッシュ値だけを保存する([ADR 0001](adr/0001-link-based-access-without-login.md))。

## アクセス

[ADR 0001](adr/0001-link-based-access-without-login.md) を参照。

- ログイン機能はない。日程調整の作成時に、回答用リンクと管理用リンクを発行する。
- 管理用リンクは推測できない長さのランダムトークンを含む。紛失すると復旧できない。作成直後の画面で、保存を強く促す。

## 入力値の制限

- 文字数は、前後の空白を取り除いてから数える。空白だけの入力は未入力として扱う。
  - タイトル: 1〜100文字(必須)
  - 説明: 0〜1,000文字
  - 回答者の名前: 1〜30文字(必須)
- 候補は、重複をまとめた後の件数で1〜25件。重複をまとめる前に送れる件数は100件まで(大量に送られたときに重い処理をしないため)。
- 候補の開始と終了は30分単位(JST で 0分か30分)。終了は開始より後で、長さは36時間以内。表では作れない値も Server Action に直接届きうるため、サーバー側で検証する。

## 日程調整

- 持つ情報は、タイトル(必須)、説明(任意)、候補(1〜25件)。
- 削除は管理画面から手動で行う。自動削除はしない。

## 候補の作成

[ADR 0003](adr/0003-one-drag-one-slot.md) を参照。

- 主催者はカレンダーで日付を選ぶ。選んだ日付が表の列になる。
  - カレンダー(1か月分、‹ › で月を移る)は常に表示する。ただし確定中の管理画面では、候補を追加できないので表示しない。日付を押すとすぐに表の列になり、列になっている日付をもう一度押すと外れる。列になっている日付はカレンダーで色を変える。
  - 日付はカレンダーだけで選ぶ(日付の入力欄はない)。カレンダーは最初に今日の月を表示し、今日の日付に下線を付ける。管理画面では、保存済みの候補があれば、その最初の月から表示する。
  - 保存済みの候補がある日付(管理画面)は、カレンダーでも表の上でも外せない。
  - 表は日付を選ぶ前から表示する(時刻の目盛りと空の列)。このときは表の見えている範囲の真ん中に「日付を選んでください」と出す。スクロールしても真ん中に残る。
- 表の1マスは30分。
- 各列では前日 18:00〜翌日 6:00 まで選べる。初期表示は日中付近で、上下にスクロールすると前日と翌日の時間帯が表示される。
- PC では、ドラッグ1回で候補が1件できる。1マスだけクリックすると30分の候補になる。
- 横にドラッグすると、始めた列から離した列まで、間の列も含めたすべての列に同じ時刻の候補ができる。列は表の並び順で数える。縦の動きで時刻、横の動きで列が決まる。
  - 例: 12/3・12/5・12/8 の列で、12/3 の 19:00 から 12/8 の 20:30 のマスまでドラッグすると、3列それぞれに「19:00-21:00」ができる。既存の候補の上からドラッグを始めると、重なる新しい候補を作れる。
- スマホでは、開始マスと終了マスを順にタップして候補を作る。同じマスを2回タップすると30分の候補になる。開始と終了を別の列でタップすると、PC の横ドラッグと同じく、その間の列すべてに候補ができる。開始を選んだ後のタップは、既存の候補の上でも終了として扱う。開始の印は、表の外のタップか Esc キーで消せる。
- 隣り合う候補や重なる候補は統合しない。重なった候補は横に並べて表示する。
- 作成中の候補(PC のドラッグ中のプレビュー、スマホで選んだ開始の印)は、横ドラッグでは対象のすべての列に出す。作成後と同じ幅と位置で表示する。重なる場合は、既存の候補もそれに合わせて並び直す。
- 候補をクリック/タップすると選択され、画面下に「この候補を削除」ボタンが出る。
- 選んだ新しい候補(まだ保存していないもの)には、上端と下端につまみが出る。つまみを上下にドラッグすると、開始・終了を30分単位で変えられる(PC もスマホも同じ)。
  - 上端はつまみを離したマスの始まり、下端はそのマスの終わりに合わせる。30分より短くはできず、上下は入れ替わらない。その列の範囲(前日 18:00〜翌日 6:00)からは出ない。
  - 伸び縮みしても候補は選んだままで、新しい候補は作らない。ほかの候補と重なってもよい。
  - 移動(長さを変えずにずらす)と、保存済みの候補の時刻の変更はできない。保存済みの候補は回答が付いているため、時刻を変えると、別の時刻への回答にすり替わってしまう。
- 選択は、同じ候補、空いたマス、表の外のクリック/タップ、または Esc キーで解除する。空いたマスのクリック/タップは選択の解除だけを行い、候補の作成や開始の選択はしない。PC で空いたマスからドラッグした場合は、新しい候補を作る。
- 日付を外すと、その列の候補も消える。その列に新しい候補があるときは、確かめてから外す。
- 管理画面で候補を追加するときは、保存済みの候補を開始時刻の JST の日付の列に描く。1件の候補が2つの列に同時に出ないようにするため。
  - 例: 12/4 の列で作った「前23:00-24:00」(12/3 23:00-24:00)は、保存した後は 12/3 の列に「23:00-24:00」として表示される。日時は変わらない。
  - 表の列は、保存済みの候補の開始日と、新しく選んだ日付からなる。
  - 保存済みの候補は灰色で表示する。表の上で選ぶと「この候補を削除」で削除でき、確認のあとすぐに保存される。管理画面の候補一覧からも削除できる。
  - 確定中も表は表示する。候補の追加(カレンダーと表の上での作成)はできないが、保存済みの候補の削除はできる。

### 表のレイアウト

- 列の幅は、表の幅を選んだ日付の数で均等に分ける。最大は表の幅の半分。最小は PC で 96px、スマホで 80px で、これを下回る場合は横スクロールにする。
- 候補ブロック1つの幅は最大 160px。
- 前日(18:00〜24:00)と翌日(0:00〜6:00)の時間帯の行は、薄い灰色で塗る。
- 各列の右端には、候補ブロックを置かない余白(24px)を常に残す。スマホでは、ここをタップして既存の候補と重なる候補の開始を選ぶ。
- 候補の保存時に、開始日時と終了日時が完全に一致する候補を1件にまとめる。既存の候補と重複した追加分は捨て、既存の候補とその回答を残す。
- 候補を作ったときの列(日付)は保存しない。候補は実際の日時で表示する(例: 「12/4(金) 2:00-3:00」)。日付をまたぐ候補は「11/20(金) 23:00 - 11/21(土) 1:00」、0:00 ちょうどに終わる候補は「11/20(金) 23:00-24:00」と表示する。

プロトタイプはブランチ `prototype/slot-grid` の `prototypes/slot-grid.prototype.html` にある。

## 回答

- 回答は、名前(必須)と各候補への可否(○ / △ / ×)からなる。コメントは持たない。
- 名前の重複は許可する。
- 回答はまとめて送信しない。操作するたびに自動で保存する。
  - 回答画面を開くと、まず名前を入力するモーダルを出す。名前を入れて「回答を始める」を押すまで、表のセルは操作できない。
  - 「回答を始める」で回答者として登録する。この時点ではすべての候補が未回答。編集用トークンを発行してブラウザに保存する。
  - 編集用トークンを保存したブラウザで開き直したときは、モーダルを出さずに操作できる状態で表示する。トークンが使えない場合(主催者が回答を削除した後など)は、保存したトークンを消し、名前の入力からやり直してもらう。
  - 自分の列のセルをタップするたびに、空欄 → ○ → △ → × → 空欄 と切り替わり、すぐに保存する。空欄に戻すと未回答になる。
  - 画面の表示はタップした時点で変える。保存に失敗したときだけ元に戻し、「保存できませんでした」と表示する。同じセルを素早く何度もタップしたときは、最後の値だけを保存する。
  - 保存待ちのタップが残っている間にページを閉じようとしたら、ブラウザの確認を出す。
  - 名前を変えるときは、自分の列の見出し(名前)をタップして同じモーダルを開き、「保存」で保存する。
- 自分の回答を変更できるのは、回答を始めたブラウザからだけ。他人の回答は上書きできない。
- 回答者は1つの日程調整につき最大50人。名前だけ登録して可否を1つも付けていない人も1人と数える。51人目は登録の時点で受け付けない。登録済みの回答者は、50人に達した後も自分の回答を変更できる。
- 回答者の列は、登録した順に並べる。名前や可否を変えても並び順は変わらない。
- 回答画面は表形式にする。行は候補(時刻順)、列は回答者。
  - 自分の列は、候補の列のすぐ右に置く。ほかの回答者は登録した順に並べる。回答者が多くても、横にスクロールせずに自分の列に届くようにするため。
  - 表は枠の中で縦にも横にもスクロールし、名前の見出しの行と候補の列は固定する。ページ全体は画面の幅に収める。
  - 回答画面にはスコアを表示せず、スコアによる強調もしない。回答者はスコアを気にする必要がないため。スコアは管理画面だけで使う。
- スマホで快適に回答できることを優先する。
- 押せる場所(ボタン、候補を作れる表、選べる候補)では、マウスのカーソルを指の形にする。管理画面も同じ。

## 画面のデザイン

- 色は、白に近い温かい背景(#fffbf6)に、抑えめのオレンジ(#f4a261)をポイントとして使う。色の案の比較で A5 を選んだ(ブランチ `prototype/colors`)。
  - オレンジを使うところ: 上の帯(淡いオレンジ)、主なボタン、カレンダーで選んだ日付、表の新しい候補、回答画面の表の見出しの行と自分の列。
  - 表の新しい候補は、オレンジを薄く(60%)塗り、一段濃いオレンジの枠線を付ける。選んだ候補は濃いオレンジで塗る。
  - オレンジの上の文字は白ではなく濃い茶色にする。明暗の差を控えめにしつつ、読みやすさを保つため。
  - 色は CSS 変数(役割の名前: page、header、accent など)で指定し、`app/globals.css` の1か所で変えられるようにする。
  - それ以外の色: 可否(○ 緑、△ 黄、× 赤)、確定(緑)、注意(黄)、エラーと削除(赤)、保存済みの候補(灰色)。文字と罫線は灰色(slate)。明るい配色だけを用意する。
- サービス名は「○△× 日程調整」(何をするサービスか、どう答えるかが名前で伝わるように)。リポジトリやコードの中の名前は meet-planner のまま。名前は `app/_lib/site.ts` の1か所で決め、ページのタイトル(「忘年会 | ○△× 日程調整」)とプレビューのサイト名に使う。
- 全画面の上にサービス名の帯を出す。○△× は回答画面と同じ色のマークで描き、読み上げではサービス名を読む。
  - 帯のサービス名は紹介ページ(`/`)へのリンク。帯の右には画面の名前を出す。名前のない画面(紹介ページ、見つからない画面)では、代わりに「日程調整を作る」(`/new`)へのリンクを出す。
- トップ(`/`)はサービスの紹介ページにし、日程調整は作成画面(`/new`)で作る。2回目以降の人が紹介を読み飛ばせるようにするため。
  - 紹介ページの内容: 見出し「日程調整を、もっとかんたんに」とひとこと説明、作成ボタン、使い方の3ステップ(候補の日時を選ぶ → リンクを送る → 集計を見て決める)、見出しのない特徴の枠(ログイン不要、スマホで答えやすい、候補をまとめて作れる)、最後にもう一度作成ボタン。
  - 使い方と特徴は、それぞれ1つの枠の中に3項目を縦に並べ、項目の間に線は引かない。特徴の枠には見出しを付けない(読み上げ用の名前「特徴」だけ付ける)。
  - 飾りは回答画面と同じ色の ○△× だけにし、画像は作らない。
- 作成画面と管理画面は、上にタイトルと説明を横幅いっぱいで置き、その下を2列にする(デザイン案の比較で B を選んだ。ブランチ `prototype/design`)。
  - 作成画面: 左にカレンダー、その下に新しい候補の一覧(1件ずつ外せる)と作成ボタン(「この内容で作成する」。日時を選ぶ「確定」と紛れないよう、確定という語は使わない)。右に候補を作る表を広く置く。
  - 管理画面: 左にリンク、その下に回答者・タイトルと説明の編集・日程調整の削除。回答画面を開くリンクはタイトルの右に置く。回答者の一覧は高さを決めて中でスクロールさせ、人数が多くても下の項目を押し出さない。右に候補の順位と候補の表。
  - スマホでは1列にし、タイトル → 左上 → 右 → 左下 の順に並べる。候補の一覧が伸びても表がずれないように、一覧は表の下に置く。
- 回答画面は1列で、表を広く使う。

## リンクの共有と案内の画面

- どのページも検索エンジンに載せない(`noindex, nofollow`)。ほかのサイトへ移るときに URL を送らない(`no-referrer`)。回答用リンクと管理用リンクは秘密の URL のため(ADR 0001)。
- リンクを LINE や Slack などに貼ったときのプレビュー:
  - 回答画面は、日程調整のタイトルと「候補の日時に ○ △ × で回答してください。」を出す。
  - 管理画面は「管理画面」とだけ出し、日程調整のタイトルは出さない。管理用リンクが誤って共有されても、中身が分からないようにするため。
  - 画像はどのページも共通で、○△× のマークだけを描く。日本語の書体を同梱しないので、画像に日本語は描かない。サービス名はプレビューのサイト名(`og:site_name`)で出す。
  - 画像の URL を組み立てるため、公開するときは環境変数 `SITE_URL` にサイトの URL を設定する。
- 日程調整がない、削除された、管理用リンクが正しくない、のどれでも同じ「ページが見つかりません」の画面にする。どれなのかは区別しない。
  - 画面の枠を先に送る作りのため、このときの応答の状態コードは 200 のままになる。
- 想定していないエラーのときは「問題が発生しました」の画面に、もう一度読み込むボタンを出す。

## 集計

- スコアは、○=2、△=1、×=0、未回答=0 として合計する。
- 順位はスコアの高い順に決める。同点のときは × の少ない方を上位にし、それも同じなら開始日時の早い方を上位にする。
- 同点時に比べる「× の数」には、未回答を含めない。× は「参加できない」とはっきり回答したものだけを数える。
- 管理画面では、候補をこの順位で表示する。各候補には、スコアと ○△× それぞれの人数を並べて出す。

## 確定

- 主催者は、候補を1件選んで確定する。自動では確定しない。
- 確定している状態を「確定中」と呼ぶ。確定中は、回答画面に確定した日時を表示する。
- 確定中は日程調整全体が読み取り専用になり、回答、候補、タイトルと説明のいずれも変更できない。回答者としての登録もできない。
  - 例外として、主催者は確定中でも回答の削除、候補の削除、日程調整の削除ができる。
  - 確定した候補を削除すると、確定も取り消される。ほかの候補を削除しても、確定はそのまま残る。
- 確定中に別の候補を選ぶと、取り消しを挟まずに確定し直せる。
- 確定は取り消せる。取り消すと、変更できる状態に戻る。

## 管理画面

管理用リンクからのみアクセスできる。

- 回答用リンクと管理用リンク(コピーボタン付き)、回答画面を開くリンク
- 確定した候補には「確定」の印を付ける
- 確定と確定の取り消し
- 候補の追加と削除(回答後も可能。後から追加した候補は、既存の回答者には未回答と表示される。削除した候補への可否は消える)
  - 追加の上限は作成時と同じ。既存の候補と重複をまとめた後に25件まで、1回に送れるのは100件まで。
  - 最後の1件の候補も削除できる。候補が0件の日程調整には、主催者が候補を追加するまで誰も可否を付けられない。
- 回答の削除(1人分をまとめて削除する)
- タイトルと説明の編集
- 日程調整の削除

## テスト

- Vitest: `server/poll` のテストは、インターフェースを通して外から見える振る舞いだけを確かめる(例: 確定中は回答できない)。DB はメモリ上の libsql に本番と同じマイグレーションを当てて使う。スコアと順位(`ranking.ts`)は場合分けが多いため、単独でもテストする。
- 候補を作る表の操作(マスの範囲から候補を作る処理)は純粋関数として切り出し、Vitest でテストする。
- Playwright: 日程調整の作成 → 回答 → 確定の主要な流れを E2E テストする。
